# ADR 0006 — Mercenary Intelligence: price from comparables, catalog bundled, Trade-bound queries

Date: 2026-11-26 · Status: accepted

## Context

PoE 1 3.30 Mercenary Warrants are priced by the combination of skills and the supports bound to
each skill. Tools such as PoEMercPricer score warrants with heuristics; the brief requires an
evidence-based asking price. poe.ninja has no warrant category; the official Trade API is the only
structured price source. Anonymous Trade searches accept one bound mercenary group.

## Decisions

1. **Price only from comparable listings** on the official Trade site (asks, labelled as such).
   Rules never convert to currency; they choose what to search and explain the result.
2. **Four comparison levels** (exact warrant, value package, similar, family baseline). "Exact" is
   verified per listing from `mercenarySkills`, never inferred from the query.
3. **Queries planned in TypeScript, executed and validated in Rust** through the existing
   `TradeService` (new `search_raw`). Rust validates every stat id against the live official list,
   allows at most one bound group and only skill ids outside it, caches 10 min, de-duplicates,
   retries once on network errors, and stores snapshots per league without seller names.
4. **Catalog bundled** (`poe1.mercenary-catalog`, Update Center "Bundled"): PoEDB build pages are
   HTML, so the catalog is generated by a script and shipped; official stat ids are re-checked at
   run time. Changes need an app release.
5. **Rules staged, never rewritten**: controlled with/without comparisons create candidates in the
   DB; only the user promotes them, and promoted rules sit beside bundled ones.

## Consequences

- No full-warrant match is possible anonymously; level 1 may be thin even when level 2 is rich.
- The lowest 20 asks per level describe the competitive end of the book, not the whole market.
- A new patch needs a regenerated catalog and a re-surveyed rule set (see CATALOG_AUDIT.md).
